agent-terminal v0.1.0 — first public release. Source only, on purpose.

## What this is

A tiny tmux-like session multiplexer in C, purpose-built so long-running
terminal AI agents (Claude Code and the like) survive terminal front-end
crashes. A per-user daemon owns the PTYs, the emulated screens and the
disk-persisted scrollback; thin clients attach over a unix socket and can die
freely. Kill the client, force-quit the terminal, reattach: exact screen,
cursor and modes restored, the child process never noticed. Panes, copy-mode
scrollback paging, multi-client attach, and an in-place daemon `reload` that
upgrades the binary under live sessions.

macOS + Linux. Zero dependencies beyond libc. MIT.

## Why there are no binaries in this release

The desktop GUI (`app/tauri`) builds and runs locally, but its `.app` bundle
is ad-hoc signed and macOS Gatekeeper **rejects** it — a downloader would get
a refusal, not an "are you sure?" prompt. Shipping that would be worse than
shipping nothing. Binaries arrive when they are signed and notarized; until
then, `make` from this tarball is the supported path and takes seconds:

    tar -xzf agent-terminal-v0.1.0.tar.gz
    cd agent-terminal-v0.1.0
    make && make test BUILD=asan
    sudo make install    # or PREFIX=$HOME/.local

Verify the download first: `sha256sum -c SHA256SUMS`.

## Security posture, stated plainly

- **The uid is the entire trust boundary.** Any process running as you —
  including a command inside one session — has full authority over every
  session: read, inject input, kill. Same model as tmux and screen; stated
  here because "run an agent inside a session" is exactly where that
  assumption is easiest to forget. Workloads that must not touch each other
  belong under different uids or in containers, not in different sessions.
- The socket lives in a 0700 directory, mode 0600, peer-uid checked on every
  connection. There is no network listener anywhere in the tree.
- Session commands go through `execvp`, never a shell; the repo contains no
  `system()` or `popen()`. The daemon is never setuid.
- The VT parser — first line against untrusted input — is an isolated,
  syscall-free library, fuzzed nightly under libFuzzer and run under
  ASan+UBSan on every PR.
- Four hardening rounds (S1–S4) landed before this tag: scrollback fds no
  longer leak into session children (`O_CLOEXEC`), client-side OOB reads on
  daemon replies are bounded, same-uid resource exhaustion is capped (wire
  geometry clamps, pre-HELLO deadlines, layout cycle guards), the GUI's hook
  viewer refuses symlink swaps and caps reads, and the install path can no
  longer leave a stale daemon silently answering the socket.
- No cryptography in the repo: SSH sessions delegate to your system OpenSSH.

Threat model and reporting: SECURITY.md.

## Verified, not claimed

Every PR runs 9 unit suites (6,352 checks) under ASan+UBSan, 28 integration
scripts on macOS and Linux, mutation tests on load-bearing guards, a
redaction scan, and workflow-hygiene checks (read-only tokens, SHA-pinned
actions). This tarball's tests ran against this exact tag before the release
was created, from the extracted tarball itself.

Full end-user acceptance logs with a real Claude Code session — 22 cases,
including crash-reattach with the same process answering and a daemon binary
upgrade under a live conversation — are in docs/UAT.md.

## Known limits (also in the README)

- Daemon **crash** (not restart) still kills children; scrollback survives on
  disk and `history` recovers it. `reload`/SIGHUP upgrades keep everything.
- No windows/tabs; max 6 panes per session.
- One combining mark per cell, BMP only.
- `systemctl --user restart` does not preserve sessions — use
  `agent-terminal reload`.
